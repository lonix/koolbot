# Design notes

Design passes for changes that are large enough, or reverse an existing decision clearly enough,
that the reasoning deserves review before any code is written. Each file here describes something
**proposed, not built** — if it has shipped, its reasoning belongs in the code's docstrings and in
the user-facing guides (`SETTINGS.md`, `WEBUI.md`, `COMMANDS.md`, `DEVELOPER_GUIDE.md`) instead.

A note here is not a commitment to build. Several of these will end with "don't build this", which
is a useful outcome to have written down.
